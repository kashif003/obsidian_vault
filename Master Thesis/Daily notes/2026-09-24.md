How the Data Extractor Works

Things We Need (Configuration & Inputs):

1. **Socket Address**: The network endpoint of the gRPC simulation server.
2. **Username & Password**: Security credentials sent as metadata to authorize requests.
3. **Interface Name**: The target system or PLC interface being queried.
4. **Sensor/Actuator Names**: Definitions containing human-readable tags and hardware addresses.
5. **Mappings**: Bidirectional lookups (`tag_to_address` and `address_to_tag`) to link tags and hardware addresses during data cleaning.
    

Objects We Make:

1. **Channel (`grpc.insecure_channel`):** The underlying communication pipe connecting Python script to the gRPC server.
2. **Variable Stub (`VariablesApiStub`):** The client object used to query variable metadata, resolve GUIDs, and pull real-time values.
3. **Logger Stub (`ValueLoggerApiStub`):** The client object used to control server-side event logging (creating, starting, stopping, and downloading loggers).
4. **Logger GUID:** A unique identifier string tracking the active server-side logging session.

Complete Workflow:

- **Step 1 - Connection Check:** Initialize the channel and verify if the server is active and ready.
    
- **Step 2 - GUID Resolution:** If the connection is stable, query the server for all variables and filter them against your configured sensor tags to retrieve their server GUIDs.
    
- **Step 3 - Chunked Logging:** Run the recording loop (`run_chunked_logging`).
    
    - _Event-Based Mode (`sampling_rate = None`):_ Uses the server-side native event logger. The server records data on change, and the client downloads the binary `.db` file when finished.
        
    - _Timed Polling Mode (`sampling_rate` set to a number):_ Bypasses the server logger. The client periodically polls values at fixed intervals and writes rows directly into a local SQLite database (noting that client-side polling can experience slight time drift).
        
- **Step 4 - Cleaning & Export:** Automatically detect the database schema (`ValueEntry` vs. `TimedLogs`), normalize timestamps (converting Windows FILETIME or Unix ticks to UTC strings), map tags to addresses, and export clean, unified `_clean.csv` reports.
